# Debug log: behavior-referenced clipping for asynchronous training

## Reported failure

Fully asynchronous Megatron runs recompute `old_log_probs` with the training policy immediately before a single
optimizer pass. The ordinary PPO ratio is therefore exactly one and its clip is inert even when the rollout was
generated by a stale policy. The existing TIS multiplier applies an upper-only cap after the PPO objective, so it
does not stop repeated suppression of stale negative-advantage tokens.

## References

The implementation follows AReaL's `ppo_actor_loss_fn` at commit `2ea770336b032139966ad4298d03fb66358dbddd`:
compute an importance ratio, clamp it to the asymmetric PPO interval, form the unclipped and clipped objectives,
and select the pessimistic maximum. SkyRL's `rollout_logprobs` corresponds to AReaL's behavior-policy
`old_logprobs`; SkyRL's trainer recompute is AReaL's `proximal_logprobs`.

VERL's rollout-correction pipeline at commit `09ac37258ea66b0cb69b2738eec3074ea4e7261c` independently confirms that
the behavior reference must be the inference policy and that rollout correction must not be silently omitted.

## Reproduction

Three behavior tests were added before the objective:

- behavior and proximal logprobs equal: the new objective must match ordinary PPO without TIS;
- a negative-advantage token below the low clip bound: its logprob gradient must be exactly zero;
- no rollout logprobs: the objective must raise instead of degrading to an on-policy loss.

Before registration, all three failed because `behavior_clip` did not exist. A mixed-generation-batch regression
also captures the existing placeholder path: partial rollout logprobs were previously replaced by zeros, which is
not a valid behavior-policy reference for trainable tokens.

## Result

`behavior_clip` now uses `exp(log_probs - rollout_logprobs)` directly in the pessimistic PPO clip and retains the
negative-advantage dual clip. It never applies the TIS multiplier. Both config validation and the loss reject
`behavior_clip` combined with `use_tis=true`, preventing the two correction mechanisms from being stacked.

Rollout logprobs are now a required input at generation-batch concatenation, trainer collation, and the objective.
TerminalBench no longer keys exact TITO assembly to the TIS mitigation flag; it keys capture and alignment to
whether the selected objective consumes rollout logprobs. Fully masked failed trajectories may carry aligned zero
placeholders, but a trainable trajectory without behavior logprobs raises.

The fully asynchronous Iris campaign configs and maintained fully async example select `behavior_clip` and disable
TIS multiplication. Synchronous defaults and every existing loss implementation remain unchanged. TIS divergence
diagnostics are still emitted for the new objective, while PPO clip metrics now describe behavior-policy clipping.

The focused CPU suite passed 139 tests. The full PR CPU gate passed 1,391 tests with 21 skips. The changed-file
lint and formatting pass also passed.
